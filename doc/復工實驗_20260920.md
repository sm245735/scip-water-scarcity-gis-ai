## 三、方法固定（不可變動）

以下五項是 binding contract，沒有「先看一下結果再回頭調」空間：

1. **五站固定**：`C0D580, C0D550, 72D080, C1D410, C1D420`。`pp01` 五站全有效才取平均；其他五變數取前三站平均。
2. **Strict complete 日**：目標與 14 天輸入窗每一天都必須同時有 (a) `strict_target_usable=True` 且 `storage_rate ∈ [0,100]` 的寶二值、(b) 六個跨站平均變數全部非空、(c) `within_station_history=True`。不做任何內插、後向補值或目標補值。
3. **14 天輸入窗**：`[t-13, t]` 連續 14 天，平展為 `14×7=98` 維特徵；目標為 `t+7`、`t+14` 的原始蓄水率。
4. **時序切分由 `target_date` 決定**：
   - `train`：`2016-01-01 ~ 2022-12-31`（明確不含 2014–2015）。
   - `val`：`2023-01-01 ~ 2023-12-31`。
   - `test`：`2024-01-01 ~ 2025-12-31`。
5. **Scaler train-only**：baseline 對 98 維輸入做 `StandardScaler`；LSTM 對 7 個跨日特徵做 `MinMaxScaler`。兩者都**只**在該 horizon 的 `train` 上擬合，val/test 絕對不進入擬合；h7 與 h14 不共用 scaler。LSTM 額外固定 `seed=42`，採 per-horizon `set_random_seed`（h14 不沿用 h7 的 RNG 狀態），不做 seed search／seed averaging；`y` 端僅以固定常數 `Y_SCALE_DIVISOR=100` 縮放，不擬合 y-scaler。

### 強調（這一段是審稿與方法章節必引的）

- **每個 horizon 的 test n = 79**。test 期間為 2024-01-01 ~ 2025-12-31，共 366 + 365 = **731 個日曆日**，79／731 ≈ **10.81%**。這是「每日可完整建樣」的比例，不是模型覆蓋率。

## 七、阻礙分項

以下四項為**尚未解決**、會直接影響第六章結論的開放議題，本輪未自行決定補救方式：

1. **水庫舊頁改版與歷史 API 拒絕**。
   `data/recovery/cwa_downloads/*_last_page.{html,png}` 仍是 v1 期間抓下的最後一頁；新的水利署水庫頁改版後舊下載流程失效。爬蟲需同時支援補歷史與單日重抓，並區分「下載失敗」「無觀測」「未設站」三類。
2. **未找到六月 LSTM weights/scaler**。
   `04. 暫存/` 兩個 keras 模型為四月版；六月 `model/20260628_220911_seed6/` 的 `.h5`、對應 scaler、`fhy_reservoir_data` 與 `codis_weatherdata_v2` 匯出不在當前備份中。**v2 是依當前快照新建的研究重建，不是六月模型載入**。
3. **氣象 `quality` flag 語意未查證，造成 complete-case 高排除**。
   `excluded_weather_window_incomplete = 5,323` 是最大排除項，佔候選 73%。目前先把被品質碼註記的列視為「不可用」，直接從 strict complete 流程排除；尚未對照 CWA 官方說明文件確認 `*8.9`、`X`、`T`、`/`、`code:*` 等語意，可能高估排除率。
4. **觀測發布延遲尚未驗證，目前假設「日終預測」**。
   `pp01_avg` 與其他五變數在 `research_weather_snapshot.csv` 以日為單位匯總；CWA 實際發布時間（含校正回報）未查證。本輪假設 t 日 24:00 後才完整取得當日六變數值，故 14 天輸入窗全部為「t 日終」已知資訊；若實際發布早於 24:00 或延遲更久，必須重新檢查可用資訊集與切割邊界。`daily_data_table.csv` 與 `samples.csv` 的 `origin_date` 即為這個「日終」假設的具現化。
