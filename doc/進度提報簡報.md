## 1. 🎯 研究動機

### 背景問題

| 問題 | 說明 |
|------|------|
| **氣候變遷** | 極端乾旱事件頻率增加，傳統統計方法難以捕捉非穩態（non-stationary）水文變化 |
| **用水集中** | 新竹科學園區為全球半導體供應鏈核心，日用水量約 18-20 萬噸 |
| **供需失衡** | 水庫蓄水量低於警戒線時，即使降雨正常，仍可能因需求飆升造成缺水 |

### 研究缺口

- 現有水資源風險評估多以「蓄水量」單一指標判斷，缺乏**供需動態視角**
- LSTM 應用於水庫預測多止於點預測（point forecast），少有**缺水事件分類器**
- 竹科供水風險研究多以**定性描述**為主，**定量模型**仍在發展

### 為何選擇寶山第二水庫？

| 原因 | 說明 |
|------|------|
| **供水主力** | 有效蓄水量 3,100 萬噸，是寶山（500萬噸）的 6 倍 |
| **聯合運用** | 水利署將「寶山-寶二聯合運用系統」視為單一供水單元 |
| **無調度變數** | 寶二為離槽水庫，降雨→蓄水映射純粹自然水文，適合 LSTM 建模 |
| **學長建議** | 研究範圍界定，避免多水庫維度過高與人為調度複雜化 |

### 4.2 資料庫結構

**PostgreSQL + PostGIS**：`thesis_analysis` 資料庫

```
reservoir_daily（水庫每日觀測）
  ├── data_date (DATE)         — 資料日期
  ├── reservoir_id (INTEGER)   — FK → reservoirs（1~112）
  ├── basin_rainfall_mm        — 集水區降雨（mm）
  ├── effective_storage        — 有效蓄水量（萬立方公尺）⭐ Label
  ├── storage_rate (%)         — 蓄水率
  └── water_level_m           — 水位（公尺）

rainfall_grid_data（TCCIP 網格降雨）
  ├── geom (GEOMETRY Point)    — EPSG:4326
  ├── data_date (DATE)         — 日期
  └── rainfall_mm             — 降雨量（mm）
```

### 4.3 訓練集建置（v2）

```
PostgreSQL（髒資料）
  ↓ 撈取寶二（id=23）2016-2023
  ↓ 日期對齊 → 2,922 天完整時間序列
  ↓ 產生 is_imputed 旗標（補值前標記）
  ↓ 補值（線性內插 ≤7 天，超過保留 NaN）
  ↓ 加衍生特徵（rainfall_7d_sum, rainfall_30d_sum, storage_diff_1d）
  ↓ 加時間編碼（doy_sin, doy_cos）
  ↓ 輸出 CSV → data/寶二訓練集_v2.csv
```

### 4.4 特徵選擇（§3.2 方法論）

> ⚠️ **重要發現**：`inflow_cms` 和 `outflow_cms` 缺值率達 97.8%（僅 25 天有觀測值）——寶二是離槽水庫，流率非每日記錄

**最終 LSTM Feature 組合：**

```python
FEATURE_COLS = [
    "basin_rainfall_tccip_mm",  # 當日集水區降雨（TCCIP 空間加權）
    "rainfall_7d_sum",           # 7 天累積降雨
    "rainfall_30d_sum",         # 30 天累積降雨
    "effective_storage",         # 當前蓄水量
    "storage_diff_1d",           # 前日蓄水變化（一階差分）
    "doy_sin",                   # 年週期 sin 編碼
    "doy_cos",                   # 年週期 cos 編碼
]
LABEL_COL = "effective_storage"  # shift -1，預測明日蓄水量
```

## 5. 🤖 模型訓練與表現

### 5.1 LSTM 回歸模型（`src/02_train_lstm.py`）

| 項目 | 設定 |
|------|------|
| **輸入** | SEQ_LEN=30（過去 30 天序列） |
| **訓練** | 2016-01-01 ~ 2021-12-31（6年，2,190天） |
| **測試** | 2022-01-01 ~ 2023-12-31（2年，638天） |
| **架構** | LSTM(64) → Dropout(0.2) → LSTM(32) → Dropout(0.2) → Dense(16) → Dense(1) |
| **Callbacks** | EarlyStopping(patience=15) + ReduceLROnPlateau(factor=0.5) |

**測試集表現：**

| 指標 | 數值 | 說明 |
|------|------|------|
| **MAE** | **211.8 萬噸** | 約佔總容量 6.8%（可接受） |
| Max Error | 528.8 萬噸 | 極端值（旱季轉雨季突增） |
| RMSE | 🔄 待補測 | — |
| R² | 🔄 待補測 | — |
| NSE | 🔄 待補測 | — |
| KGE | 🔄 待補測 | — |

### 5.2 缺水風險分類器（`src/03_train_classifier.py`）

| 項目 | 設定 |
|------|------|
| **任務** | 預測「30天內是否觸發缺水危機（蓄水量 < 1,200 萬噸）」 |
| **架構** | Bidirectional LSTM(64) → Dropout(0.3) → BiLSTM(32) → Dropout(0.3) → Dense(16) → Dense(1, sigmoid) |
| **類別不平衡** | class_weight 處理（缺水事件僅佔 4.7%） |

**測試集表現：**

| 指標 | 數值 | 說明 |
|------|------|------|
| **AUC-ROC** | **0.981** ✅ | 區分能力極強 |
| Accuracy | 77.6% | 整體正確率 |
| **Recall** | **100%** ✅ | 所有缺水事件無漏網 |
| Precision | 17.3% | 誤報較多（類別不平衡）|
| F1 | 0.296 | — |
| 缺水事件 | 30 天 / 638 天（4.7%）| — |

> **⭐ 口試亮點**：Recall=100% 代表「模型從未漏掉任何一次缺水事件」——不會讓缺水危機被忽略

## 6. ⚠️ 缺水風險分級框架

### 供需平衡理論

```
缺水風險 = f(供給面, 需求面)

供給面：LSTM 預測水庫蓄水量（%）
需求面：園區用水量（季節性加權）

風險指數 = 預測蓄水量 / 當月預期用水量
```

### 月用水量特徵（2024-2025 新竹科學園區實際值）

| 月份 | 用水量（噸/月） | 風險加權 |
|------|----------------|----------|
| 1-3月 | 147,618～168,554 | 低（枯水期+低用水） |
| 4-5月 | 152,694～179,396 | 中低 |
| 6月 | 165,529～185,609 | 中高 |
| **7-10月** | **174,496～197,228** | **高（夏季用水高峰）** |
| 11-12月 | 164,595～189,497 | 中高 |

### 風險分級矩陣（供需平衡）

| 蓄水量 ↓ / 月份 → | 冬季（11-3月） | 春季（4-5月） | 夏季（6-10月） |
|-------------------|---------------|-------------|---------------|
| **> 50%** | 🟢 低風險 | 🟢 低風險 | 🟢 低風險 |
| **30-50%** | 🟢 低風險 | 🟡 中風險 | 🟡 中風險 |
| **20-30%** | 🟡 中風險 | 🟠 高風險 | 🔴 危急 |
| **< 20%** | 🔴 危急 | 🔴 危急 | 🔴 危急 |
