### 來源追蹤與清洗規則

- `recovery.sources.content_sha256` 是原始檔內容雜湊；主鍵 `sha256` 是「相對路徑＋內容雜湊」的識別雜湊。同內容不同月份不會被漏掉。
- `recovery.raw_records` 保留原始字串與資料列序號；原始兩列表頭仍保留於來源 CSV。
- `recovery.weather` 保留每個來源版本與逐欄品質標記。
- `recovery.weather_daily` 選取站日唯一版本：月檔優先於舊總表，不逐欄偷偷混用來源；同優先序依來源識別雜湊及列號固定選擇，差異另外輸出。
- 依英文欄名映射六個變數，不依固定欄位位置。
- `*0.0`、`*859.5`、`T`、`X`、`/` 等暫不轉成有效數字，保留代碼待官方說明確認；不將它們當零。
- 負氣溫保留；-99 等明顯哨兵值暫排除。這是保守恢復規則，不代表已完成所有官方代碼查核。
- 不做內插、後向補值或目標補值。站史以獨立欄位標記，原始來源仍完整保留。
- 水庫邊界由 WKT 降為 2D MultiPolygon，原字串保留。查到 8 筆無效幾何，尚未自動修補。
- 相同來源重跑按識別雜湊跳過；每檔交易失敗會回滾，已成功來源可續跑。水庫新版本的衝突會報錯，不會默默覆蓋。未來更新來源選版策略仍需另訂。

### 寶山第二水庫

以水庫名稱查找對照，確認這份備份的本地 ID 為 23。

- 日資料：**2016-01-01～2026-04-14，共 3,757 筆**。
- 蓄水率沒有 NULL，也沒有超出 0～100 的數值。
- **268 筆 observation_time 的日期與 data_date 不同**：228 筆落後 4 天、1 筆落後 2 天、5 筆落後 1 天；另有 34 筆觀測日期晚於查詢日，必須回查原始官方紀錄與舊解析器。
- 以 2014-01-01～2026-09-18 檢查，共 **1,155 個待處理日期**，其中包含缺列及日期不一致，不能全稱為「缺日」。
- 主要缺列區間為 **2014-01-01～2015-12-31**、**2026-04-15～2026-09-18**。所有異常日見報表。

六月設定需要 2014～2025，因此目前不能直接將這份恢復資料當作原六月訓練集。

## 操作方式

在專案根目錄執行：

```bash
python3 src/recovery/bootstrap.py
docker compose --env-file .env.recovery up -d --wait db
docker compose --env-file .env.recovery build recovery
python3 src/recovery/run.py restore
python3 src/recovery/run.py test
python3 src/recovery/run.py backup
python3 src/recovery/run.py verify-backup
```

bootstrap 不覆寫既有密碼。`run.py` 將輸出與錯誤保存至 `logs/recovery/`，失敗回傳非零。
相同來源已實際重跑，864 個來源與 420,784 筆水庫資料沒有增加；容器重建後資料仍存在。
本輪五項測試覆蓋負溫、特殊碼、原始列數對帳、站日唯一性與同內容月檔追蹤，均通過。

只重建報表或指定研究截止日：

```bash
python3 src/recovery/run.py report --end 2026-09-18
docker compose --env-file .env.recovery run --rm recovery report --end 2025-12-31 --output /app/data/recovery/audit_2025
```

備份位於 `data/recovery/backups/`，使用 PostgreSQL custom 格式，附 archive list、大小與 SHA256。
`verify-backup` 將最新備份還原到獨立暫存資料庫、比對四張主要表列數，成功後刪除該驗證庫。

SQL 查詢：

```bash
docker compose --env-file .env.recovery exec db psql -U thesis -d thesis_recovery
```

已找到 `src/data_pipeline/train_end_to_end.py`、`CWA_Data_匯入_v2.py` 與 `model/BEST_MODELS.md`。
訓練程式確實採 14 天輸入、目前 14 天期距，且記錄十個 seeds。
未找到六月模型權重、scaler、`fhy_reservoir_data` 匯出、原始 `codis_weatherdata_v2` 備份或 PG_VERSION 資料目錄。
`04. 暫存/` 內的兩個 keras 模型為四月模型。成果紀錄不等於模型檔。

下一階段順序：

1. 解析尚未納入的歷史 XLS 與備份版本，優先補足 2014～2015 寶二資料。
2. 依異常日回查官方觀測時間；不能直接把四天前或未來觀測當作當日值。
3. 改造水庫補抓程式，接受起訖日期、保留原始回應、失敗重試與日誌；先驗單日、跨月與重跑。
4. 修復月檔下載的有效性判斷，優先處理重複內容、空月份及新站設站範圍，再补最新資料。
5. 固定訓練快照、固定長期站群／各欄有效站數，建立 t+7／t+14 持續值基準與簡單模型。
6. 修正目標日期切分與補值洩漏後重跑 LSTM。以 MAE/RMSE（百分點）、R²、MAPE 評估；不能把 100−MAPE 或 R² 當準確率，不能按測試集挑最佳 seed。

初次開發曾遇到 CSV 大型 WKT 欄位上限、報表 SQL 別名及來源去重問題，均已修正並重跑。
同內容來源識別修正時僅重建本輪新建研究庫的匯入內容，未更動原始 CSV 或既有其他容器。
